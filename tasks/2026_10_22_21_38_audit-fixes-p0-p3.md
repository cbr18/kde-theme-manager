# Аудит theme-profile-kit: исправления P0–P3

Status: DONE (остаточные пункты — в конце файла)

Plan: [2026_10_22_21_38_audit-fixes-p0-p3.md](../plans/2026_10_22_21_38_audit-fixes-p0-p3.md)

## Проблема

Аудит выявил критические и высокоприоритетные дефекты в bash-слое, Python/Qt-слое,
Rust-ядре, установщиках, тестах и документации. Пользователь запросил исправление
всех приоритетов P0–P3 и правило о синхронном обновлении документации.

## Доказательства

- Bash `theme-profile` принимает `.`/`..`, не очищает старые файлы при повторном
  сохранении и маскирует ошибки `cp` в `restore_from_profile`.
- Python/Rust удаление профиля принимает имена с `..`/`/` и не очищает
  `active-profile`.
- `_atomic_write_bytes` создаёт файл с правами 0644, даже если исходный был 0600.
- `revert()` не удаляет файлы, созданные за сессию; Undo/Revert доступны в
  read-only профиле.
- Пустой список компонентов трактуется как «все компоненты».
- Rust FFI разыменовывает NULL, `cargo test` не компилируется из-за отсутствия
  `src/tests.rs`, `cargo clippy` падает.
- Настройки `confirm_before_apply`, `notify_on_success`, `global_hotkey` и др.
  не используются; глобальный хоткей регистрируется с неверной D-Bus сигнатурой.
- Пути XDG захардкожены в Python/Rust/bash по-разному.
- Тесты и документация отстают от фактического поведения.

## Нефункциональные ограничения

- Не изменять пользовательские профили и `~/.config/theme-profile` при разработке.
- Не менять формат профилей без необходимости; сохранять совместимость.
- Источник правок — репозиторий; установленные копии не редактировать вручную.
- Push/deploy — только после полной проверки; в этой задаче выполнены по
  завершении, установленные копии сверены с исходниками.
- Сохранять стиль и существующие паттерны.

## Не входит в задачу

- Переписывание UI на другой фреймворк.
- Изменение лицензии и публикация релиза.
- Полная реализация Rust-паритета Theme Inspector.

## Желаемое поведение

- Недопустимые имена профилей отклоняются на всех уровнях.
- Операции apply/save атомарны, ошибки не маскируются, права файлов сохраняются.
- Undo/Revert корректны, read-only профили не меняют live-конфиг.
- Пустой выбор компонентов — ошибка, а не «все».
- Настройки, влияющие на поведение, реально работают или убраны из UI.
- Rust-ядро собирается, тестируется и не падает на NULL.
- Пути учитывают XDG и совместимы со старыми профилями.
- Документация и тесты отражают изменения.

## Заметки по реализации

- Валидация имён вынесена в общие helper-функции Python/Rust/bash.
- Атомарная запись сохраняет режим существующего файла и использует 0600 для новых.
- Снимки сессии хранят исходное существование файла, чтобы revert удалял новые.
- Для XDG используется `XDG_CONFIG_HOME`/`XDG_CACHE_HOME`/`XDG_DATA_HOME` с
  fallback на `~/.config`, `~/.cache`, `~/.local/share`.
- Глобальный хоткей **убран**: KGlobalAccel создаёт объект-компонент только для
  приложений с `X-KDE-GlobalAccel-CommandShortcut=true` в `.desktop`, поэтому
  голый D-Bus `doRegister` не давал рабочего шортката. Поле `global_hotkey`
  оставлено в `AppSettings` только для совместимости.
- `_json_argument` в Rust-биндинге больше не превращает явный `[]` в `None`:
  иначе «ничего не выбрано» применяло весь профиль.
- Release-библиотека Rust была устаревшей — пересобрана и переустановлена,
  иначе исправления ядра не попадали в деплой.

## Критерии приёмки

- `pytest` проходит, включая новые регрессионные тесты.
- `tests/test-scripts.sh` проходит, включая traversal/пустые компоненты/ошибки cp.
- `cargo test` и `cargo clippy --all-targets -- -D warnings` проходят.
- `shellcheck` не выдаёт ошибок; `qmllint` — без ошибок.
- Документация обновлена в том же изменении.

## План тестирования

- Python: валидация имён, права 0600, revert новых файлов, пустые компоненты,
  read-only undo/revert, XDG, настройки.
- Bash: `save/apply/diff` traversal, `.`/`..`, повторное сохранение, сбой `cp`.
- Rust: unit-тесты валидации, удаления активного профиля, NULL FFI.
- QML: статическая проверка проводки confirm/read-only и отсутствия hotkey-кода.

## Откат

Изменения локальны для репозитория. Откат — `git revert` коммитов задачи; данные
профилей не затрагиваются. Перед установкой/обновлением сохраняются бэкапы.
